# ADR-0009: Parity gaps and the native track

## Status

Accepted, 2026-10-25. Amended by [ADR-0012](0012-gpuix-svelte-0.3.md): the port is on gpuix-svelte 0.3.0 with `@gpuix/native` 0.11.0 (see G11)

## Context

The target is full parity with editmd. Some editmd features need capabilities that `@gpuix/native` and gpuix-svelte do not have yet, so app code alone cannot reach them.

## Decision

- Features that need native changes are left out or worked around in app code, each named with its gap id below and in the parity checklist. (A capability module, `src/app/capabilities.ts`, was planned for features that would switch on when a native change lands; none has landed, so it was never written)
- Track N contributes the missing capabilities upstream (remorses/gpuix, khromov/gpuix-svelte). For each one, open an issue that states the need first, then a PR
- Where a workaround gives the same function, ship it and record it as a gap until the native capability lands

Gaps:

- G1: textarea `selectionStart`/`selectionEnd` and `setSelection` (`@gpuix/native` `custom_elements/input.rs`, gpuix-svelte `html.d.ts`). Needed for inline format commands on a selection. Probed 2026-10-26, headless: in a focused `<textarea>`, shift-arrows, cmd-a and a drag select natively (typing replaces the selection) but `selected_text()` stays null and `on_selection_change` does not fire; `EventPayload` carries no selection or offsets. `getSelectedText` and `on_selection_change` report only painted text, which the port uses for Edit > Copy. Worked around 2026-10-27 (measured in a real window): `get_native().simulateKeystrokes` types into the focused field, so the port types a sentinel character over the selection, reads where it landed from the value the field reports (about 5ms), and takes it back with ⌘Z, which restores text and selection (`src/core/fieldSelection.ts`). Bold, Italic, Strikethrough, Inline Code, Add Link at the selection and the block commands at the caret use it. Its limits: the marks are typed as keys (one undo step each); a probe leaves its character on the field's redo stack unless an edit follows, so nothing probes for a command that may do nothing, and a refused command resets the field's value (clearing its undo); Edit Link's prefill and Remove Link need the caret's place before any edit, so they stay out
- G2: custom menu bar (`app_menu.rs`). Workaround: editmd's menus drawn as a bar inside the window, a command palette (⇧⌘/), and every shortcut matched through `on_window_key` (see the G2 detail below)
- G3: multiple windows in one process, window tabs. Workaround: one process per document ([ADR-0008](0008-windows-and-ipc.md)). GPUI itself knows native tabs (`tabbedWindows`, `toggleTabBar:` are in the addon's symbols); gpuix exposes neither a second window nor tabs to JS
- G4: explicit `highlight` ranges on `<markdown>` (`markdown.rs` skips them). Narrowed 2026-10-26: a `query` highlight with `activeIndex` washes exactly one occurrence of a string (probed headless), so a changed run inside a Block is washed by its text and occurrence (`src/core/changedText.ts`); editmd's underline under the run is drawn too, as a 2px bar along each rect `getPaintedHighlights()` reports. What is left: a run that spans painted lines is washed line by line, and text removed inside a Block has no inline marker (no zero-width run to place one at)
- G5: print. Workaround: export through `satteri.markdownToHtml` to a temporary HTML file and open it in the browser. What that page lacks (front matter, relative images, diagrams, editmd's styles) comes from the export, not from gpuix: the port already paints the whole page to a PNG (`--snapshot`, `src/app/snapshot.ts`), which could go to a PDF of the page as shown; what gpuix lacks is a print panel (NSPrintOperation)
- G6: open-file event (Finder double-click, `open -a`). Cold-launch argv only for now. Widened 2026-10-25: Finder hands a `.app` its documents through an Apple Event (`odoc`), not argv, and gpuix's native host does not handle it (`on_open_urls` appears in remorses/gpuix only in `packages/gpui-terminal`, not in the host crate), so a Finder open fails even on a cold launch. Only `editmd-gpuix <path>` from a shell opens a file. Checked 2026-10-25 and again 2026-10-27: `open -n -a dist/editmd-gpuix.app sample.md` started one process whose argv holds no file, and its window painted an empty untitled document (the window's own after-mount screenshot). So `Resources/Info.plist` leaves editmd's document types out until G6 lands: declaring them would offer the app in Finder's Open With for files it cannot open. Outside gpuix, a small native launcher as the bundle's executable could take the Apple Event and start the binary with the file as its argument; that is a packaging change the port has not made
- G7: spelling check in the textarea. Checked 2026-10-26 in a real window: misspelled words typed into the open field get no marks after 2s; GPUI draws the field itself, with no NSSpellChecker behind it
- G8 (long-term): a native rich-text element that takes styled runs and reports caret, selection and hit-test events, through custom-element registration (remorses/gpuix #110 and #120, both open). It would let prosemirror-model/state and y-prosemirror drive a GPUI view and replace click-to-edit. That would be a separate future ADR. Until then the field holds source: outside a field the page has no caret, so the keyboard cannot move into a Block or a diagram; a code fence typed without its closing fence makes every Block after it code, where editmd's input rule makes one closed block
- G9 (added 2026-10-25): `<markdown>` styling that `GpuixTheme` (`theme.rs`) has no token for: link colour, h1 and h2 bottom rules, blockquote rail and text colour, table cell borders and header fill. The text theme covers colours and sizes it does have tokens for. (The code block language label was listed here; `GpuixMetrics` does size a native code header, `mdCodeHeaderTextSize` and `mdCodeHeaderPaddingY`, host.d.ts:204-205, but the port draws the card and its label itself, so the label is no longer a G9 item)
- G2 detail (2026-10-26): `@gpuix/native` 0.10.0 and 0.11.0 (latest) export no menu API. Its `packages/native/src/app_menu.rs` calls GPUI's `set_menus` with a fixed App menu (Services, Hide, Hide Others, Show All, Quit) and Window menu, and leaves out an Edit menu on purpose because AppKit takes menu key equivalents before the window sees ⌘C. The port draws editmd's menus inside the window instead (`src/ui/MenuBar.svelte` over `src/app/menu.ts` `menuBar`). Upstream ask: let JS set the menus, with actions dispatched back to JS
- G9 detail (2026-10-26, spikes S13 and S14): `GpuixTheme` has no token for link text colour (`textMuted` paints only the underline), table cell borders, header fill or content width, list item spacing or indent, bullet shape, heading letter-spacing (`letter-spacing` is ignored by gpuix), or inline code size and border. What it has is used: `fontSans: '.SystemUIFont'` (the system font, bold and italic kept), `accent` (list markers and the quote rail: set to the muted colour), `syntax.*` (all the text colour, as editmd has no syntax colours), heading sizes. Headings, quotes, code blocks, front matter and diagrams are drawn by the port's own views around `<markdown>`
- G11 (added 2026-10-26): no dashed borders (remorses/gpuix #60, open; `border-style: dashed` paints solid in 0.10.0, probed). Worked around: the port draws editmd's dashed blocked-image box and deleted-block line as `<svg>` with `stroke-dasharray` (an `<svg>` wider than about 1000px paints nothing, so long lines are drawn in segments). `@gpuix/native` 0.11.0 (published 2026-10-20, with gpuix-svelte 0.3.0) adds `borderStyle: "dashed"`, which would close G11; the port stays on 0.10.0 / gpuix-svelte 0.2.0 by the user's decision of 2026-10-25. 0.11.0 also adds `outlineWidth`/`outlineColor`/`outlineOffset` (a focus ring outside a box, e-frontmatter-edit), `scrollbarColor`/`scrollbarWidth`, and `registerFont` (which may let a field take SF Mono, G13; untested); it still has no menu, close or quit hook, field selection or open-file event (read from its d.ts files). Amended 2026-10-30, on 0.11.0: the blocked-image box is a `border-style: dashed` border; the deleted-block line still draws `<svg>` dashes until GPUI's dash length for a 2px line is compared with WebKit's 6px
- G12 (added 2026-10-26): no window close hook. The close button, gpuix's Close Window and Quit end the process when the last window closes (`tick()` returns false). The port saves a file's unsaved edits from a process `exit` handler, but cannot ask about an untitled document the way NSDocument does, because the window is already gone
- G13 (added 2026-10-26): a `<text>` element rejects `.SystemUIFont` as its font family (spike S13), so window chrome text (menu bar, find bar, dialogs, legend) paints in GPUI's default face. The same holds for the system mono (spike S16): native `<markdown>` takes `.AppleSystemUIFontMonospaced` (SF Mono), but a `<text>` or `<textarea>` style refuses it and every other name for SF Mono (`SF Mono`, `.SF NS Mono`, `ui-monospace`), so the text fields (Source mode, an open code or front matter field) paint in Menlo. A `<textarea>` also refuses `selection-color`, inherited or set on its own class, so a field's selection keeps gpuix's accent at 35% where editmd's is 22%; painted text takes it. Narrowed 2026-10-28: the read-only mono lines (front matter, definition and HTML lines, diagram messages) paint through native `<markdown>` as inline code with a transparent wash, one paragraph a line, which takes SF Mono and wraps as editmd's do (`src/app/monoLines.ts`; probed: gpuix's `<code>` also takes SF Mono but never wraps)
- G14 (added 2026-10-26): no way to mark a window as having unsaved edits. NSDocument puts a dot in the close button while a document is edited (`setDocumentEdited`); the native addon calls `setDocumentEdited:` inside GPUI (it is in the addon's symbols), but gpuix-svelte's window helpers (`lib/window.d.ts`: title, activate, minimize, zoom, fullscreen) expose no binding to it, so the port shows `— Edited` in the title instead. A binding is the upstream ask
- G15 (added 2026-10-26): no trackpad pinch. editmd's page zooms with a pinch (`EditorBridge.swift:47`, WKWebView magnification); GPUI receives `magnifyWithEvent:` (in the addon's symbols), but gpuix's events carry no magnification: its scroll event has only `deltaX`/`deltaY`, `precise` and `touchPhase` (`@gpuix/native` `index.d.ts`)
- G17 (added 2026-10-28): no quit hook. GPUI binds ⌘Q (and the App menu's Quit) to its own quit, which takes the key before any element or window listener and ends the process without Node's `exit` event, so neither the port's own ⌘Q command nor its exit-time save runs: an edit typed less than a second before ⌘Q, before the autosave, is lost (measured in a real window: `"saved":false`, an earlier autosaved edit on disk; ⌘Q reached neither `onkeydown` nor `on_window_key`). editmd's NSDocument saves on quit. Upstream asks, any one of: a JS hook before quit, a way to rebind ⌘Q in `app_menu.rs`, or GPUI's quit ending through `tick() === false` so gpuix-svelte's `process.exit(0)` runs and the exit save with it
- G16 (added 2026-10-28): font smoothing. editmd's page sets `-webkit-font-smoothing: antialiased` (style.css:51), which turns off macOS's stem darkening; GPUI draws text with the system's default smoothing, so regular-weight text paints heavier (ink in matching boxes 25-35% more; bold headings the same). `@gpuix/native` 0.10.0 has no smoothing or antialiasing option (its d.ts files searched)
- G10 (added 2026-10-25): a checked state in the accessibility attributes. gpuix-svelte passes `role`, `aria-label`, `aria-description`, `aria-id`, `aria-expanded`, `aria-selected`, `aria-valuetext` and `aria-level` to VoiceOver, with no `aria-checked`, so a task's checkbox (`role="checkbox"`) reports its ticked state as `aria-selected`, the only boolean state there is. How VoiceOver announces that is not checked

## Consequences

- The parity checklist in [parity.md](../parity.md) marks every gap with its id
- Gaps G1 and G4 limit the editing and attribution experience compared with editmd until upstream changes land

## Evidence

- gpuix-svelte `src/window.ts` (read 2026-10-25): `prompt_for_paths` open picker only, no save dialog
- Native inline-text analysis of `@gpuix/native@0.10.0` and the 0.11.0 diff (2026-10-25): no inline runs for host text, `<markdown>` skips explicit highlight ranges
- `GpuixTheme` fields and Comet defaults in remorses/gpuix `packages/native/src/theme.rs` (read 2026-10-25), compared with a screenshot of the compiled binary on `sample.md` and editmd's `web/src/style.css`@9e889e6 (G9)
- gpuix-svelte `CLAUDE.md`: fixed app menu, one window per process, no clipboard, open-URL, print or appearance API
- gpuix-svelte 0.2.0 `lib/html.d.ts` lines 58-65 (`GpuixAttributes`, read 2026-10-25) and the docs' Guide, "Window and desktop helpers": the accessibility attributes listed in G10, no `aria-checked` (G10)
