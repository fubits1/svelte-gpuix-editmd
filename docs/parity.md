# Parity with editmd

The baseline is editmd itself at `9e889e6` ([kirahowe/editmd](https://github.com/kirahowe/editmd)). Every row states what editmd does, with the editmd file and line that does it. Nothing here comes from this port's plan or code. Each row was compared on the same input in both apps:

- Rendered pages: editmd's own `--snapshot` mode (`Sources/editmd/Headless.swift:116-135`) against the port's window, at the same width.
- Window states, menus and sheets: editmd driven inside its own process, as its `SelfTest.swift` drives it, against the port's window.
- Format commands, Add Link, merges and reference settling: editmd's own editor run headlessly on the same cases as the port's core.
- Command-line modes: both apps' output on the same fixtures.

The screenshots, outputs and scripts behind this comparison are kept outside this repository. Each mark states its result, and the port's own checks it cites (`test.ts`, `e2e/*.e2e.ts`, `src/**/*.test.ts`) are in this repository.

Marks:

- `done`: the target matches the source in what the row states
- `partial`: what differs is named
- `missing`: the port has no such feature
- `gap Gn`: gpuix lacks what the feature needs ([ADR-0009](adr/0009-parity-gaps-native-track.md))
- `pending`: not compared yet

Status as of 2026-10-30: every row is compared and marked: 5 done, 76 partial (one of them, `f-serializer`, by design), 5 gap, 1 not applicable (`f-crash`), none missing. Rows the port changed since are re-marked from its own checks; their pictures from both apps are not re-taken yet. 72 rows were compared by pictures from both apps. The other 15 were compared by output, self-test lines, editmd's editor run headlessly, real-window tests, or the code the row cites.
